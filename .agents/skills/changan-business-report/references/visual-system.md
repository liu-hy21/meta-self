# 视觉与空间规则

## 参考中的共同语言

三份材料均采用接近16:9的横版画布、白色背景、深蓝或黑色标题、蓝色主体结构，辅以浅灰蓝分区。SDA材料更偏工程架构，VHR材料更偏业务角色和服务链路；融合分析兼有架构、矩阵和测算。不要把三者压成一种固定卡片模板。

来源与代表图见 [参考页证据](source-study.md)。下列参数分为观察与建议，建议值是复现时的起点，不是原稿统一标尺。

## 版面骨架

- 原稿常见：品牌页眉约占顶部8%，标题约位于页面高度8%–15%，判断区约15%–28%，主体约30%以后。侧边距常见页面宽度2%–4%。不同页有明显差异。
- 新稿建议：按1280×720画布组织，外边距32–40px；已存在母版时让位于母版安全区。标题、结论区、主体共享左对齐线。
- 结论区与主体留16–24px，平行栏目间留12–20px，节点内边距8–12px。同类节点保持同一套间距；不同层之间的间距略大于层内间距。
- 有母版时保留页眉细线、标识和页码秩序；没有时不用复制全部口号、英文标题或密级章。英文只在术语辨识或模板确有需求时出现。
- 留白用于分开业务层级和阅读阶段，不为极简而删掉证据，也不为显得丰富加入无意义图标。

## 颜色承担什么

原稿直接文本颜色可见：SDA的`#00467F`；VHR的`#1F3864`、`#17457E`、`#1F2937`、`#64748B`；融合分析的`#1E293B`、`#475569`。这不是完整主题色统计，未把继承色与全部图形填充算入。

建议配色角色：

| 角色 | 建议色 | 使用方式 |
| --- | --- | --- |
| 标题/层级骨架 | #17457E | 标题、层名、关键节点 |
| 主业务结构 | #0070C0 | 主平台、共享能力、关键结论 |
| 常规正文 | #1F2937 | 解释与节点内容 |
| 辅助信息 | #64748B | 来源、口径、次级标识；保持可读对比度 |
| 分组背景/细边 | #EDF3FA / #CBD5E1 | 平台清单、表头以外的轻分区 |
| 缺口/本次整合核心 | #EF7D00 | 一处关键缺失层或整合层 |
| 问题/风险 | #D9001B | 少量有依据的矛盾与风险词 |

跨平台对照可给不同主体稳定色，如SDA第5页的蓝、橙和其他主体色；这些色代表主体，不自动代表好坏。避免同一颜色在相邻页同时表示“某平台”和“高风险”。跨页改变含义时给图例。

## 几何、圆角与连线

- 架构层、对标表、共享横条优先直角或很小的圆角。业务角色/平台摘要可低圆角。
- 以1280px宽画布为例，节点圆角建议0–4px，较大的角色分组建议6–10px；这是提炼后的建议，不是原稿测得的精确半径。避免大圆角胶囊和厚重浮层。
- 边线建议0.75–1.25pt，重要边界可到1.5pt；不要让所有边线都争抢注意。
- 连线优先直线或直角折线，少交叉。箭头只用于真实的数据流、调用、业务推进或因果方向，邻接关系不必全部连线。
- 容器表达归属；跨列横条表达共享；细分栏表达独立；虚线可表达隔离域或规划范围，但必须以本页图例/标签确定含义，不能固定把所有虚线解释成“未建设”。
- 在层间绘制安全边界时注明穿越条件，如适配、脱敏、授权或单向推送。来源没有这些细节时保留为待确认，不补造控制措施。

## 排版与信息密度

原稿SDA大量使用长安引力体，直接设置字号以9、10、12、14、24pt等为主；VHR混用苹方与微软雅黑，直接设置字号多为9–12pt；融合分析也存在更小字号。密度是观察，不意味着新稿应该照搬最小字号。

- 有授权字体与模板时跟随；缺字体时用微软雅黑或可用的中文无衬线，检查替换后的换行，不把苹方视为Windows必有字体。
- 新稿常规16:9起点：标题24–28pt，页首判断15–18pt，主体13–16pt，密集图标签10–12pt，必要脚注9–10pt。现场投屏时提高字号、拆分密集页。优先删重复和拆页，不优先缩字。
- 同一层级保持字号、字重、对齐方式一致；节点名加粗，解释常规；对比表的维度列清晰，数值列与单位对齐。
- 强调一个词组或关键数字即可，不整段涂红或整页加粗。避免为了凑齐行宽把普通词句拆成逐字竖排。
- 业务图优先中文业务名，技术名放同节点的次层级或括号内。表格保留单位，不靠口头解释补齐。

## 最有价值的构图

1. **同层对齐**：SDA第5页，平台为列、SaaS/PaaS/IaaS为行，重复能力可以直接横向比较。共享三电能力用跨列条表示。
2. **缺失层定位**：VHR第5页，研发系统在下、售后业务系统在上，橙色横条放在二者之间表示缺失服务平台。右表补充差距，不能用橙色框替代依据。
3. **图文按层对应**：VHR第6页，左图三层与右侧三段职责同高。右边解释左边“这一层为什么需要”，避免重复抄所有节点。
4. **分散到入口**：VHR第4页，平台按业务类别分行，底部先展示安全/权限阻隔，再展示融合转译入口。位置构成了论证顺序。
5. **整合与保留分开**：融合分析第8页，上层保留业务应用，中间高亮统一湖仓，底部单列治理贯穿与AI关系。突出本次改变，不暗示所有系统合并成一个。
