# 可视化逻辑

把业务事实转换成实体、属性、关系、数值、状态和来源，再投影到有明确含义的行、列、顺序轴和边界中。页面不是把文字放进框里，而是让空间直接表达业务关系。

开始画图前读取：

- [视觉与空间规则](../../references/visual-system.md)
- [可视化数据与空间逻辑](../../references/visualization-logic.md)

## 快速判断

- 需要表现“从哪里到哪里”：使用链路或流程结构。
- 需要表现“谁和谁重复、共用、独有”：使用平台列 × 能力层行的矩阵。
- 需要表现“当前与目标差多少”：使用双栏对照或左图右表。
- 需要表现“谁使用、做什么、得到什么”：使用角色并列和底部流程。
- 需要表现“数量如何变化”：使用有刻度的图表或带单位的测算表。
- 需要表现“谁负责什么、何时完成”：使用责任矩阵或计划表。

位置、颜色、大小、边线、线宽、箭头和容器一次只表达一个定义好的维度。没有数值尺度时，架构框大小不表示能力强弱，线宽不表示数据量，颜色不表示好坏。

## 短项 token 列表

当页面需要罗列字段、数据类型、协议、排查对象、控制点或其他同类短项时，使用独立的小框 token 表达，而不是把多个短项写成斜杠分隔的长句。

- 每个 token 只承载一个短项，例如 `[用户ID] [事件] [设备] [地区]`；较长的解释、状态和结论留在 token 列表外。
- token 使用统一的轻量几何：直角或约 `3px` 小圆角、`1px` 细边、约 `18–22px` 高、左右 `4–6px` 内边距；同一组 token 的字号、边框和间距保持一致。
- 同一语义组使用同一组浅色填充、边框和文字色；token 的颜色只表达类别或归属，不同时表达风险、完成状态或数量大小。
- token 列表使用左对齐、自动换行和 `3–6px` 间距；不要为了填满一行拉伸 token，也不要把长句硬塞进一个 token。
- “已有 / 待建设 / 待确认”等状态放在 token 列表外，通过状态标签或独立颜色表达；token 只表达对象、属性或控制点。
- 参考第一页“数据类型 / 字段示例”列的视觉语言：字段先分组，再以小框连续罗列，允许一行内有多个 token；第二页的排查对象和控制点沿用同一套语法。

## 文字颜色约束

除页面标题外，正文、节点名、标签、口径和状态文字只使用黑色或白色。颜色多样性放在框的填充、边框、节点底色和留白分组上，不用彩色文字表达阶段或风险。

- 深色表头、深色节点和深色主结构使用白字；浅色框、浅色 token 和正文区域使用黑字。
- 状态仍可保留彩色框、色带或边线，但状态文字保持黑色；例如橙色缺口使用橙色底框或左边线，文字仍用黑色。
- 页面标题可以使用主题色；卡片标题、阶段标签、法规口径不自动视为页面标题，默认使用黑色或白色。
- 检查页面时先去掉填充色：文字仍应可读，且不能依赖红、橙、蓝等彩色文字才能理解关系。
