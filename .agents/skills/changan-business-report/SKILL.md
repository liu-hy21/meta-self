# 长安技术业务汇报

这是父级路由 skill。它负责判断当前任务需要哪些能力，并加载对应子模块；详细规则放在子模块和 references 中，避免把所有内容一次性带入上下文。

## 使用流程

1. 先读 [通用原则子模块](modules/changan-business-report-core/SKILL.md)。建立“结论—证据—时间—口径—状态”清单。
2. 根据任务加载子模块，不默认读取全部模块：

   | 任务 | 读取模块 |
   | --- | --- |
   | 需要画架构图、数据流、流程图、指标图或分析空间布局 | [可视化逻辑](modules/changan-business-report-visual/SKILL.md) |
   | 需要写页首判断、标题、结论、对标表文案 | [业务写法](modules/changan-business-report-writing/SKILL.md) |
   | 需要选择页面骨架或给整份汇报排页 | [页面模式](modules/changan-business-report-patterns/SKILL.md) |
   | 需要做对标、成本/人力/效率测算、方案选择或推进计划 | [决策与测算](modules/changan-business-report-decision/SKILL.md) |
   | 需要阅读参考PPT、核对页码、区分现状与方案、提取版式证据 | [材料证据](modules/changan-business-report-evidence/SKILL.md) |

3. 先确定页面要回答的问题，再选择坐标结构。不要先画装饰框再填文字。
4. 让标题、主图、表格和脚注共享同一套实体名称、状态和口径。
5. 制作PPT时保持图形、表格、标签和连线可编辑，并以实际渲染结果检查遮挡、溢出、换行和阅读顺序。

## 组合规则

- 单页只设置一个主关系：顺序、层级、比较、因果、数量、责任或区域。其他关系降为辅助标注。
- 视觉对象必须能还原为“实体—属性—关系—数值—状态—来源”。没有来源或口径的数字、颜色和线宽不能制造结论。
- 现状、已有、待建设、建议、预计、待确认必须保持可区分；参考材料中的数值、组织归属和方案不自动成为当前事实。
- 空间承担语义：横向可以表示流程或比较，纵向可以表示层级或阶段，容器表示归属，跨列表示共享，边界表示范围。具体含义必须在本页一致。
- 页面需要罗列字段、数据类型、协议、排查对象或控制点时，优先采用可视化逻辑中的短项 token 小框；不要把同类短项重新串成一条斜杠分隔的长句。
- 除标题外，正文、节点名、标签、口径和状态文字只使用黑色或白色；类别和状态差异通过容器填充、边框、节点底色或位置表达，不用彩色文字制造第二套编码。
- 参考页用于提取结构和视觉语法，不复制草稿批注、重叠对象、错字、缺单位或未经核实的行业判断。

## 输出前检查

- 读者只看标题和主图，是否知道页面在回答什么？
- 图上的任一对象能否追溯到实体类型、关系、口径和来源？
- 图与表是否分工，是否避免把同一句话重复两遍？
- 对标、测算和计划是否保持同一范围、单位、时间和分母？
- 去掉颜色后，主关系是否仍能通过位置、标签和线条读懂？

用户只要成品时直接交付成品，不附带内部模块清单或设计过程讲解。
