# 角色模拟聊天主界面设计

## 意图

角色模拟的第一任务是像聊天一样试聊，而不是先阅读资料表。保留左侧架构图作为“系统如何工作”的可视化摘要，右侧改成微信式对话工作区，资料、评测和版本操作降为辅助层。

## 目标

- 首屏直接看到角色与对话窗口。
- 消息区支持用户/角色双向气泡、时间与检索状态。
- 底部输入区支持 Enter 发送、Shift+Enter 换行、重新开始。
- 架构图继续显示原文、检索、资料、回复四个节点，并随试聊状态变化。
- 资料与评测继续保留，但不抢占首屏。

## 非目标

- 不改变 persona action、检索算法或蒸馏数据结构。
- 不复制真实微信品牌素材，不引入新的 UI 依赖。

## 方案

1. 资料优先：保持现状，聊天仍在 Tab 内。改动小，但不符合角色模拟的主要任务。
2. 左架构 + 右聊天主视图：保留架构图，右侧采用聊天顶栏、气泡消息流和底部输入器；资料/评测作为分区切换。选择此方案，最符合用户路径，也最接近参考项目的聊天工作台。
3. 全屏聊天 + 架构抽屉：聊天更沉浸，但架构不再持续可见，不符合“保留架构图展示”。

## 视觉决定

沿用 MetaSelf 的纸张、墨绿、珊瑚色和细边框；聊天主视觉使用浅纸色背景、角色左侧气泡、用户右侧墨绿气泡，输入器固定在聊天区域底部。减少解释性文字，把版本、截止日期、检索状态压缩到聊天顶栏与状态条。
