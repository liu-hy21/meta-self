# 财商资产结构数据分析页设计

日期：2026-11-13

状态：已选择方案，等待构建检查和用户确认后进入实现

## 1. 意图

在财商的“资产结构”区域增加“数据分析”入口。点击后进入独立的 `/finance/analysis` 页面，页面内用 URL 页签切换三个板块：

1. 市场信号分析
2. 我的资产结构：纯指标分析
3. AI 分析

本次只实现前端页面、导航、占位内容和状态表达，不实现市场信号计算、指标计算、AI 调用、报告生成或新的数据库存储。

AI 分析板块要明确展示未来的输入来源：真实当前市场信号、我的资产结构纯指标，以及《五层资产配比与市场阶段研究》文档。当前只显示“待接入/待生成”的前端状态，不能用虚构的实时结论填充页面。

## 2. 已确定的用户要求

- 用户选择 A 方案：进入独立的数据分析页。
- 用户批准使用 URL 页签结构：`/finance/analysis?view=signals|metrics|ai`。
- “资产结构”仍是资产总览主页面，分析页是从资产结构进入的研究工作区。
- 现有资产金额隐私规则继续有效：涉及金额的展示默认隐藏，由眼睛按钮统一切换；本次页面后续如果出现敏感金额，复用现有 `FinanceVisibilityProvider` 和敏感金额组件。
- 当前阶段不写具体分析逻辑。

## 3. 现状与关联代码

- 财商总览入口在 `src/app/(main)/finance/profile/page.tsx`，数据由服务端查询后交给 `FinanceAssetsSection`。
- 资产结构卡片和“更新资产”按钮在 `src/components/finance/finance-assets-section.tsx`。
- 项目已有关系模块的数据分析页，采用独立路由和 URL 查询参数页签，相关参考为 `src/app/(main)/relation/analysis/[personId]/page.tsx`、`src/components/relation/analysis-tabs.tsx`。
- 顶部标题和左侧财商导航目前主要按 `/finance/profile` 判断，需要将 `/finance/analysis` 纳入财商上下文并显示“财商 · 数据分析”。
- 配比研究文档位于 `docs/五层资产配比与市场阶段研究.md`。它是 AI 分析未来的策略依据，不在本次页面中解析或执行。

## 4. 目标与非目标

### 目标

- 在“资产结构”标题区域提供清晰的“数据分析”按钮。
- 进入独立分析页后，默认打开“市场信号分析”页签。
- 三个页签可通过 URL 直接访问、刷新和分享。
- 三个板块拥有统一的页面骨架、页签状态、空状态和未来数据接入位置。
- 延续当前财商页面的复古终端视觉、卡片、颜色和响应式布局。
- 移动端页签可横向滚动，主要内容不被挤压。
- 有清晰的返回资产结构入口。

### 非目标

- 不请求外部行情，不判断当前顶部或底部，不实现任何实时信号。
- 不计算资产收益、回撤、集中度、流动性或五层目标偏差。
- 不调用 AI，不接入模型设置，不生成报告。
- 不新增 Prisma 表、API、Server Action 或分析快照。
- 不修改已有资产录入、价格拉取、总资产隐藏和资产结构计算逻辑。

## 5. 方案比较与选择

### 方案 A：独立页面 + URL 页签（已选择）

路径为 `/finance/analysis?view=signals|metrics|ai`，页面内复用项目已有的查询参数页签模式。优点是入口与分析工作区边界清晰，刷新和分享后仍保留当前板块，未来每个板块可以分别接入数据。代价是新增一个页面骨架和导航组件。

### 方案 B：独立子路由

使用 `/finance/analysis/signals`、`/finance/analysis/metrics`、`/finance/analysis/ai`。每个板块边界最清楚，但当前只有前端占位时会重复页面导航，未来也需要在三个路由间同步公共状态。

### 方案 C：资产结构页面内展开或右侧抽屉

保留 `/finance/profile`，在同一页面展开分析或打开抽屉。它离资产上下文最近，但会增加主页面复杂度，并让大屏和移动端的阅读顺序变得拥挤；也不符合用户已经选择的独立分析页。

选择 A，是因为项目的关系分析已经使用类似的 URL 页签方式，而且本次需要未来逐步接入三类不同数据源，独立工作区更容易保持页面边界。

## 6. 页面结构

### 6.1 资产结构页入口

在 `FinanceAssetsSection` 的“资产结构”标题行右侧增加 `Link`：

- 文案：`数据分析`
- 目标：`/finance/analysis?view=signals`
- 视觉：与“更新资产”按钮同一操作区域，但使用次级边框按钮，避免与保存资产动作混淆。
- 不读取数据、不改变资产结构卡片和金额隐藏状态。

### 6.2 独立分析页

页面从上到下包含：

1. 页面标题区：`财商 · 数据分析`、简短说明、返回“资产结构”链接、资产金额隐私开关。
2. 分析页签：`01 市场信号分析`、`02 资产结构指标`、`03 AI 分析`。当前页签由 `view` 查询参数决定，无效参数回退到 `signals`。
3. 当前板块内容区：使用统一卡片和边界，避免三个板块同时堆叠。

### 6.3 三个前端板块

市场信号分析：展示“市场信号”标题、待接入状态、若干未来指标卡占位，以及“当前阶段判断将在接入真实数据后生成”的空状态。不得展示假装实时的涨跌数值或顶部/底部判断。

我的资产结构：纯指标分析：展示未来指标分组占位，例如五层权重、QQQ/VOO 差额、消费防守层上限、现金安全垫、黄金占比和目标偏差。当前显示指标名称与“待计算”，不产生实际数值，也不执行文档中的买卖建议。

AI 分析：展示报告输入来源卡片：`真实当前市场信号`、`我的资产结构纯指标`、`五层资产配比与市场阶段研究`；展示“AI 报告待生成”状态和未来报告区域。当前不发送请求、不生成文本、不宣称有结论。

## 7. 实现边界与组件建议

- 新增 `src/app/(main)/finance/analysis/page.tsx` 作为服务端页面入口，解析 `searchParams.view`。
- 新增一个财商分析页签组件，保持和关系分析页签的语义结构一致，但使用财商的 CSS 变量和 Tailwind 类，不复用关系模块的视觉类名。
- 新增一个财商分析内容组件或按板块拆分三个轻量组件；当前内容以静态前端占位为主。
- 在 `FinanceAssetsSection` 增加入口链接。
- 在顶栏和左侧导航中将 `/finance/analysis` 视为财商上下文。
- 复用 `FinanceVisibilityProvider`；如果占位内容不展示金额，仍保留页面接入点，避免后续指标接入时绕过统一隐私状态。
- 不增加依赖，不修改数据库 schema，不引入外部数据源。

## 8. 验收标准

- 从 `/finance/profile` 的“资产结构”区域可以点击“数据分析”进入 `/finance/analysis?view=signals`。
- 直接打开 `/finance/analysis` 时默认显示市场信号分析。
- 三个页签点击后 URL 与内容同步，刷新后仍停留在当前页签。
- 无效 `view` 值不会报错，并回退到市场信号分析。
- 三个板块都有明确的前端占位、未来数据来源和待接入状态，没有伪造实时分析结果。
- 返回资产结构链接可用，资产结构原有金额隐藏和更新资产流程不受影响。
- 移动端可以访问和切换页签，页面无横向溢出。
- 类型检查、专项校验、构建和相关页面手工验证通过。
