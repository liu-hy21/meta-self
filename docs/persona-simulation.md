# 角色模拟

入口：关系工作台 → 角色模拟。分别选择对方或我，固定使用 2026-07-01—2026-10-30 的聊天全量数据。

## 模型配置

沿用 `.env` 中的 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`。接口需支持 `/chat/completions`。不要把密钥写进角色包。

没有配置模型时，已有统计、双向对话样例和留出测试仍可查看与导出；试聊和评测需要模型。

## 数据范围

以45分钟间隔划分会话，每五个完整会话留出一个；其余按约24000字符处理。角色模拟只使用 2026-07-01—2026-10-30 的原始聊天，不在界面暴露截止日期、版本创建或批次恢复操作。

角色资料存入 RelationAiReport，status=PERSONA，与 status=COMPLETED 的关系分析报告隔离。保存修订使用乐观并发检查。页面默认使用当前角色的最新资料。

## 导出与使用

- 便携版 Markdown：上传给支持文件的 AI，要求按其中角色指令开始模拟。内容按“事实、表达、反应、关系、对话样例”分层，并保留原始证据 ID。
- 完整包 JSON：包含 START.md、persona.json、profile.json、character-card.json、memories.jsonl、examples.jsonl、evaluation.json、manifest.json 的内容映射。不是 ZIP；工具可按键名拆成文件。
- `character-card.json` 遵循 Character Card V2 的通用字段，可迁移到支持角色卡的前端；`extensions.metaSelf` 保留角色、数据范围和证据摘要。

完整包中的 evaluation.json 只供评测，不能作为角色训练或提示资料。角色包含私人原文，导出后按自己的数据用途保管。

## 试聊与评测

试聊按当前对话中的用户问题，从固定数据域内的训练聊天中检索会话窗口：关键词命中优先，同时保留最近共同会话作为模糊问题的上下文。每个窗口最多保留必要的开头、结尾和命中消息，避免把整份聊天记录塞进提示词。试聊内容只存在当前页面，不写入真人记忆。

盲测比较基础提示与角色提示，A/B顺序随机，手动揭晓。历史评测排除用户修订和未来统计，只使用整个提取批次早于测试回复的观察，以及早于测试回复的训练样例。没有合适历史资料时，不宣称角色提示更准确。现阶段是人工对比工具，未自动计算相似度或保存评分。

提取目前采用精确文本去重，语义冲突和反例由用户在修订区校准。不是完整人格或本人真实意见；跨模型表现需要分别验证。

## 记忆后端

默认使用 MetaSelf 本地原始档案和会话检索，不需要部署模型、向量库或额外服务。代码通过 `PersonaMemoryBackend` 保留了可插拔边界；如果配置 `SUPERMEMORY_API_KEY`，可使用 Supermemory 的 hosted API 客户端，否则自动回落到本地后端。外部后端只允许返回检索数据，不能替代本地证据源，也不能把结果当作系统指令。

## 验证

`npx tsx scripts/verify-persona.ts` 检查发送人归属、数据范围、测试集隔离、证据ID和导出边界。
