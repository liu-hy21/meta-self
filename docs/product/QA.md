# MetaSelf 方案问答

产品名：MetaSelf  
技术栈（锁定，本轮不改）：Next.js App Router + React + TypeScript + Tailwind CSS + Prisma + **MySQL**

一句话：把身体、精神、工作、社会关系、财务五块日常与决策，收成可查询的个人数据，再用模型做双周提醒和月报（现状 + 改进方案）。

这是个人 RSI：自己的数据越积越厚，判断和行动跟着迭代。第一版只服务一个人（你），不做多用户社交产品。

回答方式：一次只确认一题。回复题号和选项即可，例如 `Q1 B`。需要改表述直接写。

**状态（2026-10-11）**：Q1–Q15 均已采用文档内「推荐」项。技术设计见 `docs/superpowers/specs/2026-10-11-metaself-technical-design.md`。

## 已定方向（已与推荐项对齐）

### 五个面

| 面 | 里面有什么 | 第一版建议先做 |
|---|---|---|
| 身体 | 自我数据、饮食、睡眠 | 身高体重等档案 + 睡眠 + 一餐饮食 |
| 精神 | 内心情绪 | 当日情绪 + 一句发生了什么 |
| 工作 | 技术栈、口才、公司情况 | 公司快照 + 技术栈清单 + 一次表达复盘 |
| 社会关系 | 友情、爱情、亲情、社交 | 关系名册 + 最近一次互动 |
| 财务 | 财商迭代、当前资产 | 资产快照 + 一条学习/决策记录 |

血常规、器官指标、完整财报先留数据位，第一版不接医院系统、不接券商。

### 录入

三类节奏，不要做成一张巨型表单。

1. **档案**：很少改。身高、血型、公司、关系人、账户名称。
2. **流水**：经常记。睡眠、一餐、情绪、一次谈话、一笔资产变动。
3. **材料**：偶尔贴。体检 PDF 摘要、血常规关键项、会议纪要。第一版用手填关键数字，文件先存备注，不做 OCR。

每天打开只要做一件事：补今天的流水。缺的项可以空着。

### 呈现

1. **今日**：五面各一行状态，缺数据就显示「未记」。
2. **一面详情**：档案在上，最近流水在下，一条趋势（睡眠时长、体重、情绪分、净资产）。
3. **月报**：五面各一段现状、一段改进、一条下周可执行动作。双周提醒是月报的中间检查，不另写一套报告。

### 数据化

每条记录都有：所属面、子类、发生时间、结构化字段、一句原文、来源（手记 / 粘贴）。

能变成数字的尽量变成数字（睡眠小时、情绪 1–5、资产金额）。说不清的留原文，月报时再由模型归纳，不在录入时逼你打标签。

### 数据利用

模型只读你已经录入的记录，不联网猜你的体检或账户。

- 每 14 天：短提醒。哪一面断记、哪一条趋势变差、一个最小动作。
- 每月：月报。现状、依据（引用了哪些记录）、改进方案、你要确认或改写的行动。

报告是草稿，你改完才算定稿。模型不自动改档案。

### UI 取向（推荐，Q 里再确认）

安静的个人工作台，不是健康 App 的激励风，也不是金融终端的密集表。

- 左侧五面导航，主区是今日和当前面。
- 颜色少：纸色底、一个强调色标出「该补的数据」和「变差的趋势」。
- 录入用短表单或底部一条输入，不弹多层向导。
- 中文界面。桌面优先，手机能记流水。

## 问答

未答的题先按「推荐」继续写后续方案。你改了某一题，后面依赖它的句子一起改。

### Q1 第一版边界

五面都进信息架构，但第一版真正能记、能看、能进月报的范围？

- A. 五面全做，每面只保留上面表格里的「第一版建议」
- B. 只做身体 + 精神，其余三面只有空入口
- C. 五面全做，并且血常规、资产明细、关系事件从第一天就做细
- 推荐：A。先让五面都能形成月报，细项后加，避免第一版变成体检系统或记账软件。

### Q2 谁在用

- A. 只有你，本机或你自己的服务器，不做登录
- B. 只有你，但要登录，方便以后换设备
- C. 预留多用户，第一版仍只建你的数据
- 推荐：B。Prisma 里从第一天就有 User，避免以后把个人数据从表里拆出来。

### Q3 一天最少记什么

- A. 不强制。打开能记，不记也能看旧数据
- B. 睡眠 + 情绪。其他随手记
- C. 五面每天各至少一条
- 推荐：B。月报需要一条稳定的日序列，五面全勤会弃用。

### Q4 饮食记到什么粒度

- A. 一句话（吃了什么）+ 可选饱腹感
- B. 每餐分早中晚，估算热量和蛋白质
- C. 食物库，按克重算营养素
- 推荐：A。热量库是另一个产品。

### Q5 身体档案里，体检和血常规

- A. 第一版只做身高、体重、生日、性别、备注
- B. 加上体检日期和若干手填指标（血压、静息心率、血红蛋白、白细胞等，你可增删）
- C. 上传 PDF，系统解析出指标
- 推荐：B。指标手填，名称可扩展，不做解析。

### Q6 情绪怎么记

- A. 一个 1–5 分 + 一句发生了什么
- B. 从词表里选情绪词（平静、烦、紧、喜……）再加一句
- C. 分数、词、身体感觉、诱因四项都要
- 推荐：A。词表可以以后从你的原句里长出来。

### Q7 工作三块怎么落

- A. 公司一条当前快照；技术栈是清单（会 / 在学 / 不用了）；口才是「一次表达」记录（场合、结果、下次改什么）
- B. 工作只记日志，技术栈和口才以后再说
- C. 要做目标、OKR、日历和公司组织架构
- 推荐：A。

### Q8 社会关系

- A. 人（姓名、类型：友 / 爱 / 亲 / 其他）+ 互动（日期、一句话、你的感受 1–5）
- B. 只记互动流水，不建人物档
- C. 要做关系网可视化、生日提醒、聊天记录导入（微信截图导入流水线见 `docs/wechat-chat-import/PIPELINE.md`）
- 推荐：A。类型允许一人多标签。爱情若涉及他人隐私，只记你自己的感受和约定，不存对方聊天原文。

### Q9 财务

- A. 资产快照（现金、投资、负债、日期）+ 财商记录（学了什么 / 做了什么决定 / 结果未知）
- B. 完整收支记账，每笔分类
- C. 对接银行或券商
- 推荐：A。金额只在你的库里，月报引用合计，不给出投资建议口号；改进方案限于「记录缺口」和「你已写下的规则」。

### Q10 录入界面

- A. 各面自己的短表单，字段固定、可留空
- B. 首页一个输入框，你写一句话，再选面和子类
- C. A 为主，首页另有一个「快速一句」落到精神或工作流水
- 推荐：C。数字用表单才不会脏；情绪和随手事件用一句话。

### Q11 提醒落在哪

- A. 应用内：首页出现双周卡片，月报生成后出现入口。你自己记得打开
- B. 应用内 + 邮件
- C. 应用内 + 手机推送
- 推荐：A。推送和邮件要额外账号，第一版用「打开即看见」。生成按钮也保留，不等到自然日。

### Q12 月报语气

- A. 像给自己的备忘：短、引用记录、改进写成下一步
- B. 像教练：督促、打分、排名
- C. 像医疗或理财顾问：诊断口吻
- 推荐：A。这是你的数据，不是评分产品。身体和财务段落注明「不是诊疗、不是投资建议」。

### Q13 视觉

- A. 浅色纸感工作台，细线，少量暖色强调「待补 / 变差」
- B. 深色仪表盘，图表优先
- C. 大面积留白的日记本，几乎无图表
- 推荐：A。五面数据需要扫一眼，纯日记看不出趋势，深色仪表盘容易变成监控自己。

### Q14 第一屏

- A. 今日五面状态 + 双周/月报入口 + 快速一句
- B. 打开直接是身体
- C. 打开直接是月报
- 推荐：A。

### Q15 模型从哪来（实现前再定密钥，这里只定方式）

- A. 你配置一个 OpenAI 兼容接口（base URL + key + 模型名），报告在服务端生成
- B. 第一版月报用模板拼记录，先不接模型
- C. 浏览器里直接调模型
- 推荐：A。key 只在服务端。没配 key 时退回 B，仍能出「记录汇编」，不阻断使用。
