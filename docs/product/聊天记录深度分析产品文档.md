# 聊天记录深度分析产品文档

版本：v1.0 草案 · 2026-11-10

适用范围：MetaSelf 人物关系工作台，先支持“我与一个人物”的双人聊天。本文是后续开发方案，不代表这些能力已经实现。既有功能以本次检查的 relation/types.ts 与 metrics.ts 为依据。

## 1. 产品目标

把聊天档案变成可探索、可比较、可回到原文验证的关系资料。用户不仅能看到“聊了多少”，还能回答：

- 什么时候开始频繁联系？变化是短期波动还是持续发生？
- 谁更常开启对话？对方是否接住、延续或重新开启话题？
- 双方回应节奏有什么差异？差异是否只发生在工作日或特定时段？
- 共同话题如何形成、持续、消失？哪些话题通常聊得更深入？
- 谁分享经历、提出问题、表达需求、提供支持、安排见面？
- 出现分歧后，如何澄清和恢复交流？
- 双方沟通习惯如何变化？哪些观察证据充分，哪些还不能判断？

每个分析模块都形成“问题 → 指标 → 趋势 → 证据 → 解释”的完整链条。不要只增加数字卡片，也不要把长篇 AI 报告直接堆进页面。

## 2. 既定产品约束

1. 人物管理是计算入口：点击“计算分析/重新分析”才执行计算并持久化。
2. 数据分析页只读取已保存的快照；打开页面、切换页签不会触发全量分析或模型调用。
3. 主要状态为“待分析/已分析”，运行时增加“分析中”，失败显示明确错误与重试入口。
4. 原文、数据分析、AI 分析仍是独立工作区，允许通过证据互相跳转。
5. 界面遵循当前偏好：功能优先，不加装饰性大标题、英文眉题、人物 Logo。
6. 本期不修改人物属性的三类结构；本文中的分析维度不受“三类人物属性”限制。

## 3. 数据能支持什么

| 数据层 | 可用输入 | 可支持的分析 | 限制 |
|---|---|---|---|
| 消息元数据 | 时间、发送者、类型、稳定 ID | 数量、节奏、轮次、会话、活跃时间 | 不能判断是否已读或真实在线 |
| 文字原文 | 文本、引用关系（若导出包含） | 话题、提问、分享、支持、分歧 | 反讽、语境、省略可能误判 |
| 媒体占位符 | 图片/语音/视频等类型 | 使用频率及组合 | 无内容时不得推断图片含义或语音情绪 |
| 后续增强 | 语音转写、图片文字、通话时长 | 媒体主题、沟通渠道差异 | 仅在真实导入这些字段后开放 |
| 人工补充 | 用户标记事件、修正标签、填写备注 | 时间线解释、校正模型结论 | 与自动结果分开标注来源 |

“没有记录”不等于“没有交流”；电话、线下见面和其他平台活动可能不在档案中。

## 4. 统一分析单位与口径

### 4.1 时间、消息与覆盖范围

- 默认时区 Asia/Shanghai；时间先规范化再分日、周、月。
- 自然周从周一开始；边界不足一周标为“非完整周”。
- 保存导入覆盖范围、实际首末消息时间、解析失败数、媒体占比、可分析文本占比。
- 在已确认完整的导出区间内，无消息日补零；覆盖未知的区间显示缺失，不补零。
- 同时间消息用原始顺序稳定排序。只有可靠来源 ID 相同才自动去重，不能仅因文字和时间相同删除。
- 系统消息单列，不参与双方投入、回应和主动性统计。

### 4.2 消息、表达轮次、会话三种单位

| 单位 | 定义 | 用途 |
|---|---|---|
| 消息 | 导出记录中的单条消息 | 类型、字数、数量 |
| 表达轮次 | 同一发送者连续发言，且相邻间隔不超过 5 分钟；对方发言立即终止当前轮次 | 降低拆成多条发送造成的偏差 |
| 会话 | 相邻非系统消息间隔超过 45 分钟开始新会话 | 发起、持续、话题分析 |

5 分钟与 45 分钟是产品默认参数，不是关系事实。计算时保存参数；高级设置可选其他阈值，修改后需要重新分析。比较两个快照时要求参数一致。

会话“跨度”是末条时间减首条时间，不等于实际聊天时长。可另提供“活跃间隔累计”：累计不超过 5 分钟的相邻间隔，但仍不得命名为实际在线时长。

## 5. 指标体系

### 5.1 规模与结构：这段档案由什么组成

| 指标 | 计算口径 | 展示与下钻 |
|---|---|---|
| 消息总量 | 非系统消息，双方分别计数；另列系统消息 | 双方堆叠柱，点击查看消息 |
| 文字量 | 文本字符数，排除类型占位符；明确是否含标点 | 双方趋势与每轮次中位数 |
| 媒体结构 | 各类型数量 / 非系统消息数 | 类型条形图，点击筛选原文 |
| 活跃日率 | 有非系统消息的天数 / 已覆盖自然日数 | 日历热力图 |
| 双方活跃日 | 同一天双方都发言的日期数 | 与单方活跃日并列 |
| 连续联系 | 最长连续活跃日、当前连续活跃日 | 时间线区间 |
| 会话规模 | 会话数、每会话消息/轮次中位数与 P90 | 分布图，查看最长/最密集会话 |
| 发送拆分倾向 | 每表达轮次消息数中位数 | 解释消息数量差异 |

不要仅凭消息占比判断谁更投入：同时展示轮次占比和文字量占比。

### 5.2 时间节奏：联系发生在什么时候

- 日/周/月消息量、轮次数、活跃日和会话数。
- 星期 × 小时热力图，支持双方切换与重叠展示。
- 工作日/周末差异；没有节假日数据时直接叫“周一至周五/周末”。
- 夜间交流占比，默认 23:00—次日 06:00，明确标注时段。
- 每日首次与末次消息分布；不能据此推断起床、入睡时间。
- 两次会话间隔分布、最长无记录区间、沉默后的重新联系。
- 同比对齐：选两个等长区间比较；不足完整区间时同时提供每日均值和覆盖天数。

核心交互：刷选趋势区间 → 下方列出该区间会话 → 打开会话原文。

### 5.3 发起与延续：对话是怎么开始、怎么继续的

| 指标 | 定义与分母 | 注意事项 |
|---|---|---|
| 会话发起占比 | 某方首先发言的会话数 / 可判定会话数 | 档案第一段可能是截断会话，单独标记 |
| 首轮接续率 | 发起后 24 小时内对方有下一轮发言的发起次数 / 有完整 24 小时观察窗的发起次数 | 只代表后续发言，未必在回答开场 |
| 双向会话率 | 双方都发言的会话数 / 会话数 | 区分单向通知 |
| 延续深度 | 每次会话双方交替的轮次数 | 长消息不直接等于深交流 |
| 重新联系占比 | 间隔超过 24 小时后的首轮发送者分布 | 阈值可配置 |
| 会话末轮占比 | 各方成为会话最后发言者的比例 | 不称“终结话题率”或“冷场率” |

语义增强可识别“新话题发起、追问、补充、话题回访”，但这些必须与确定性计数分层。

### 5.4 回应节奏：多久接续、在什么情境下变化

建立独立的回应样本表。以表达轮次为基础，计算前一方轮次末条到另一方下一轮首条之间的间隔。

同时保留两组指标：

1. 会话内接续间隔：45 分钟会话内的交替发言，适合描述正在交流时的节奏。
2. 跨会话接续间隔：在 24 小时观察窗内找后续另一方发言，呈现较长间隔；语义未确认时不叫“问题回复速度”。

分别展示双方 P50/P75/P90、样本数、间隔分布，以及工作时段/夜间/周末分层。没有观察到后续发言但观察窗完整时归为“窗内未观察到接续”；档案结尾观察窗不足时归为“观察不足”，不能当作超慢回复。

语义层的“问题回应覆盖率”以模型确认的提问与后续回应配对计算，允许跨多轮回答、部分回答、转移话题和无法判定，不可简单按问号匹配。

### 5.5 话题地图：聊什么，怎样随时间变化

分三层组织：主题类别（工作、学习、日常、家庭、情绪、娱乐、关系、出行等）→ 具体主题（某个项目、考试、旅行计划）→ 原文片段。类别可多选，不强制每段只属于一个主题。

可挖掘：

- 各主题覆盖会话数、轮次数、活跃周数；多标签占比之和允许超过 100%。
- 主题由谁首次提出、谁更常延续，双方的共同主题与单方主题。
- 新出现、持续讨论、沉寂、重新出现的主题。
- 各主题的会话轮数、回应间隔、追问比例与支持表达。
- 主题迁移，例如从工作事务延伸到个人经历；展示时间顺序，不推断因果。
- 话题集中度与多样性，比较不同月份，但同时显示文本样本量。

呈现：主题趋势图 + 可排序主题表。词云只能作为辅助，不能充当主题分析。

### 5.6 表达与沟通画像：双方怎样交流

确定性指标：每轮字数、长短表达分布、表情使用、问号/感叹号使用、媒体混合、连续发送等。

AI 语义维度：提问/追问、分享近况、表达观点、请求帮助、提供建议、共情回应、确认理解、幽默、表达边界、主动澄清。每项显示双方的出现次数、适用样本数、代表性证据和随时间变化。

最终画像描述具体行为，如“在工作主题里更常给解决建议，在个人近况中更常追问”。不从聊天自动确定 MBTI、人格障碍、真实动机或固定性格；人物档案中的 MBTI 继续由用户填写。

### 5.7 情绪与支持：情绪如何被表达和回应

- 情绪标签按片段多选：愉快、担忧、疲惫、失落、烦躁、平静、无法判断。
- 区分“说话者表达自己的情绪”“转述他人”“玩笑/引用”，避免错误归因。
- 情绪表达之后的回应：倾听、认同、安慰、建议、转向其他话题、没有足够上下文。
- 支持交换方向：谁发出需求、谁提供支持；仅在识别到明确需求时计算支持回应比例。
- 同类困扰的回访：是否再次询问进展、是否持续跟进。

展示片段级情绪趋势和支持事件列表。不要用一句“你想多了”或单个表情直接判断关系态度。

### 5.8 分歧、修复与行动：从交流走向事件

分歧候选需要上下文支持，区分观点不同、玩笑和明确冲突。修复行为可包括解释、确认误解、道歉、重新表述、协商边界。

事件链示例：提出分歧 → 澄清 → 明确回应 → 恢复交流。恢复发言不自动等于问题已经解决。

行动类事件：邀请、约定、计划、承诺、后续反馈。提取发起者、涉及日期、事项、回应、结果证据。结果仅在聊天明确确认时标为完成，否则为未知。支持用户修正与补充。

这些事件组成“关键节点时间线”，可叠加到消息趋势上，但只展示先后与共现，不写成“这个事件导致关系降温”。

## 6. 关系温度与阶段变化

保留“关系温度”入口，默认展开其依据，避免一个数字掩盖复杂变化。

### 6.1 双层结果

- 行为层：联系频率、双向参与、接续节奏、持续性四条独立趋势。
- 语义层：支持交流、共同计划、个人分享、分歧修复等有证据的观察。

首期优先完成独立趋势；综合温度作为后续实验功能，必须标注“互动活跃度参考”，不可解释为喜欢程度。

### 6.2 综合指标候选口径

如启用综合分，每周按四个维度等权：

- 频率：该周每日平均双向会话数在固定基线期的经验百分位。
- 双向参与：该周双向会话数 / 总会话数。
- 接续：该周有完整观察窗的发起中，24 小时内出现对方接续的比例。
- 持续性：该周双方活跃日数 / 已覆盖天数。

映射为 0—100，所有分量保留原始值。基线期、公式和参数写入快照；缺分量则综合分不生成，不能偷偷补默认值或改变权重。初始建议至少有 4 个完整周作为基线，至少 5 个可观察发起事件作为周接续分量的最低样本量；阈值需通过样本审查调整。

该分只用于同一人物、相同基线与版本下的时间比较，不做人物间排名。重设基线会产生新版本，旧结果可回看。

### 6.3 阶段与变化点

输出“持续增加、持续减少、结构改变、样本不足”等候选变化，并列出变化维度。初期采用相邻完整双周比较，展示绝对变化、相对变化、样本数；前期为零时不显示无限增长百分比。

AI 对变化给出可能解释、支持证据和其他解释。用户可将阶段命名为“刚认识”“备考”“忙碌期”等，系统不擅自命名为“暧昧期”“疏远期”。

## 7. 页面结构与交互

数据分析工作区内设二级页签：总览、时间节奏、双向互动、话题与表达、关键事件。AI 深度解读保留在现有 AI 分析页，数据页可展示已持久化的语义标签与结果。

| 区域 | 内容 |
|---|---|
| 顶部工具栏 | 日期范围、对比区间、分析时间、快照版本、分析状态 |
| 总览 | 4—6 项核心指标、趋势、最值得核查的 3 项变化、数据覆盖信息 |
| 时间节奏 | 日历、星期小时热力图、会话间隔、活跃区间 |
| 双向互动 | 发起/接续、轮次、文字量、回应分布、长间隔事件 |
| 话题与表达 | 主题表、主题趋势、沟通行为对比、支持交流 |
| 关键事件 | 分歧修复、计划与邀请、人工标记、阶段变化 |
| 证据抽屉 | 原文及前后上下文、时间、发送者、命中依据、跳转完整原文 |

所有图表支持空状态；图表下方提供表格或可读数值。筛选条件体现在 URL，支持返回后恢复位置。点击周/月区间可下钻日和会话。

“筛选”只对持久化事实表/聚合结果做查询；任意区间的 P50 等分位数必须由保存的回应样本计算，不能平均每周中位数。读取时的轻量聚合允许发生，但不得重新解析原文或重新执行语义分析。

## 8. 计算任务与持久化

### 8.1 用户流程

人物管理点击计算 → 创建任务并返回“分析中” → 后台解析与验证 → 生成确定性事实及聚合 → 原子发布新快照 → 显示“已分析”和完成时间。

语义分析可独立触发；数据已分析与 AI 已分析分别显示状态，避免把纯统计完成误认为 AI 结论已生成。

重新计算时继续提供上次成功结果。失败保留上次快照，并显示“本次失败”；有新数据时显示“已分析 · 有更新”，不在进入页面时清空结果。

### 8.2 建议保存的数据

| 对象 | 关键内容 |
|---|---|
| 分析任务 | 人物、源版本、参数、排队/运行/成功/失败状态、进度、错误、起止时间 |
| 分析快照 | 源内容哈希、覆盖范围、时区、算法版本、参数、统计摘要、生成时间 |
| 事实索引 | 消息 ID、轮次、会话、回应样本、时间桶、来源定位 |
| 语义结果 | 片段、主题/行为/事件标签、模型与提示词版本、证据 IDs、人工修正 |
| 用户标注 | 事件命名、标签纠正、排除项、备注及修改时间 |

源 ID 应在追加消息或重新导出后保持稳定；当前顺序编号不能长期作为唯一来源标识。必要时建立来源 ID 到内部 ID 的映射。

同一人物、相同源版本和参数的重复点击复用任务；避免并发覆盖。旧任务晚完成时不得覆盖新源版本快照。分析失败和取消不能发布半成品。

## 9. AI 分析方法与证据质量

1. 按会话/连续片段切分，保留适量重叠上下文；不逐条孤立分类。
2. 提取结构化主题、沟通行为和事件，保留无法判定项。
3. 按阶段汇总，再生成跨阶段解释；报告记录覆盖了多少文本、多少会话。
4. 大档案分批处理；若只采样，按月份、双方、主题和变化区间分层，并在报告注明“样本分析”。
5. 结论引用真实消息 ID 和上下文范围；校验引用存在且属于当前人物和源版本。
6. 将模型声称的置信度与经过人工评估的准确性区分开；未校准前以证据数量、覆盖度、冲突证据呈现可靠程度。
7. 用户可标记“不准确”、修改标签或补充背景；人工修正独立保存，重算不覆盖。

涉及批量原文发送时，任务界面说明本次使用的数据范围和模型服务。文字脱敏可作为可选配置；原文数据不得写入普通应用日志。

## 10. 当前版本需要优先修正的问题

本次源码检查发现以下问题，进入深化开发前应先处理：

- 当前会话计数包含系统消息，而双方计数排除系统消息，口径不一致。
- 当前回应仅统计 45 分钟内的相邻异方消息，长间隔被排除，不可代表整体回应速度。
- 当前按消息而非表达轮次计算回应，容易受连续拆分发送影响。
- 当前温度每周使用同一个全局平均回应间隔，不能反映周级节奏变化。
- 当前温度以全档案最高周消息数归一化，追加高峰后可能改变旧周得分。
- 当前周桶只记录有消息的周，连续无记录区间没有明确体现。
- 当前中文“话题”采用连续汉字段正则提取，属于粗糙文本片段频次，不是分词或语义主题。
- 当前档案日期以 UTC 字符串截日，上海零点可能显示前一天；应统一日历日期语义。

这些是实现口径问题，不能靠增加图表或 AI 文案解决。

## 11. 分期交付

| 阶段 | 范围 | 可验收产物 |
|---|---|---|
| P0 数据可信 | 时间/覆盖/去重规则、稳定 ID、系统消息隔离、任务与快照版本 | 原文与指标可对账；页面不触发重算 |
| P1 行为深度 | 轮次、会话、主动接续、回应分布、完整时间线、区间比较 | 总览、时间节奏、双向互动及证据下钻 |
| P2 语义深度 | 主题、沟通行为、情绪支持、计划事件、修正反馈 | 结构化语义表与证据；独立 AI 状态 |
| P3 纵向洞察 | 阶段变化、综合温度实验、长期回访、版本比较 | 可解释趋势和带证据的阶段报告 |

建议先完成 P0/P1，再做 P2。第一版深度页面宁可少几个语义结论，也要让用户能查清每个数量和时间指标的来源。

## 12. 验收标准

- 已覆盖日期范围内，各时间桶之和等于同口径总量；双方之和等于非系统消息总数。
- 系统消息、空档、跨日、同时间消息、连续拆分发送、档案末尾均有边界验证。
- 零样本显示“暂无样本”；零分母不产生 NaN/Infinity，不用 0 伪装缺失。
- 打开数据页不会产生新分析任务；刷新不会改变快照时间与版本。
- 重复点击不产生重复有效任务；失败不破坏上次结果。
- 每个语义结论至少有可打开的证据或明确标为无法判断；不允许编造引用。
- 在固定人工审查集上分别统计主题、问题回应、事件提取的错误类型，达到约定质量门槛后再默认展示，不能以“模型置信度高”替代验收。
- 对比页明确两个区间长度、覆盖率、参数版本；不混合不同计算口径。
- 默认不推断线下事实、已读情况、真实心理或关系因果。
- 性能目标：在约定本机环境、预热后，万条级快照页首屏目标 1 秒内；后台任务显示进度。以实际测量验收，AI 耗时单独统计。

## 13. 完成后的体验

用户从人物管理启动分析，看到结果已保存；进入数据页后先看到“发生了哪些可验证的变化”，再按时间、双方行为、话题或事件逐层查看。发现一个值得注意的趋势，点击便能回到对应对话，结合上下文形成自己的判断。
